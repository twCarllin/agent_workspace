Agent Workspace · 架構與流程說明

一套流程，
選擇不同的 AI 工具。

把「工作怎麼做」放在共用核心。
透過 Adapter，交給 Codex 或 Claude Code 執行。

30 秒講法：像同一份工作單，可以交給不同團隊。工作目標與驗收標準相同；Adapter 負責把指令轉成各工具能接受的格式。
01 / 分工

誰決定流程？誰執行工作？

Harness 在這裡指管理 AI 工作的執行環境。這個專案的目標，是讓流程能跨執行環境使用。

02 / 一次任務

從需求到完成，走同一條路

  1. 01 → 說清楚

    定義工作

    寫下目標、限制與完成條件。例如：修正登入錯誤，且原有測試仍通過。

  2. 02 → 選工具

    交給 Adapter

    選 Codex 或 Claude Code。Adapter 把任務與設定轉成該工具的執行方式。

  3. 03 → 執行與檢查

    實作、審查、測試

    工具修改檔案。依任務等級進行審查，並用完成條件檢查結果。

  4. 04 → 留下紀錄

    保存結果

    記錄變更、測試證據與任務狀態。符合流程規則後，再提交成果。

檢查未通過：記錄原因 → 依流程修正或取得必要決策 → 再檢查。
執行中斷：保存狀態 → 核對檔案與證據 → 從正確步驟恢復。
用一個例子說明

同樣修登入錯誤，換工具也能沿用工作單

共用內容：錯誤重現方式、預期結果、可修改範圍、測試指令。

隨工具改變：派工命令、模型設定、事件格式、權限處理方式。

換工具接手時，讀取已保存的工作單、檔案與證據。工具內部的對話和推理狀態不保證能轉移；跨工具恢復仍需驗證。

04 / 接下來

實作與驗證進度

  1. 修評測：已用共用安裝器建立測試環境；兩種工具可選。
  2. 補 Adapter：已統一事件與結果格式；完整權限需明確指定。
  3. 跑實際流程：本地案例、Codex 與 Claude Code 原生 CLI 四個案例全部通過。
  4. 改善安裝：已加入變更預覽、修改衝突偵測與寫入失敗還原。

常見問題

完成後，就不需要 Codex 或 Claude Code 了嗎？

仍需要執行工具。目標是讓共用流程不綁定其中一家，能依需求選擇工具。

以後可以加入第三種工具嗎？

可以往這個方向擴充。需要建立新的 Adapter、確認工具能力，並通過同一組驗收案例。缺少必要能力時，必須明確回報限制。

換工具後，結果會完全一樣嗎？

不保證。模型與工具能力不同，產出的程式可能不同；工作目標、驗收條件與證據格式應保持一致。
