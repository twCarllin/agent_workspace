# Flow next 唯讀操作建議

## 授權與目的
使用者已同意第一批計畫：操作盤點、唯讀 next 入口、相關測試、一次實際使用證據；並多次要求繼續執行。沿用此授權，不增加自動執行或新 gate。

## 系統理解與影響
- `flow.py:106` 的 select_run 已處理明示 run 與唯一活動 run 選擇。
- `flow.py:133` 的 status 讀熱狀態、歸檔、失敗與 next_action，但建議是概括文字。
- `run_evidence.py:62` validate_evidence_snapshot 核對 schema 2 快照；validate_review、check_items 提供審查與交付檢查。
- `flow.py:362` finish 執行驗證、歸檔與提交，有副作用，不適合直接用來取得建議。
變更限新增命令與文件，不修改既有 status/watch/finish 契約。新 CLI 結果契約使用 Tier 2 與獨立審查。

## 操作盤點與設計
啟動需需求／計畫授權；實作與審查取捨由 agent 判斷；驗證快照有效性、task 憑據及 item 對帳由既有程式檢查；提交訊息與範圍由呼叫端提供；恢復需核對實際 commit。
新增 `flow.py next --run-id <id>`，預設輸出 JSON，接受 --json；可省略 ID，沿用唯一 run 選擇。
固定欄位：run_id、state、action、command（argv list 或 null）、reason、blockers（字串 list）。成功讀取建議退出 0，選擇／輸入錯誤沿用 2。command 只在必要參數已知時提供，不使用佔位值或猜測授權文字、審查結果、提交訊息。
優先處理終態、paused／未知狀態、準備後 HEAD 與已存在 commit 恢復、計畫缺口、進行中的 task、驗證、審查、item 對帳、收尾。
終態 completed/partial/aborted/failed 不建議重新執行；partial 明列未交付項。
ready_to_commit 只有 matching_commit 證據成立才提供 finalize argv；HEAD 改變且不匹配時回報阻擋。
Tier 2 熱狀態或 archive 只能使用同 run，異 run 熱狀態須明列阻擋；缺歸檔／任務時回報缺口。未完成 task 不得跳到收尾，可回報 resume_task 並保留 task step 意圖，不宣稱程序存活。
驗證使用 validate_evidence_snapshot；缺失／失敗／過期則 action verify，test_command 已知時提供 run_verify argv 並 --reuse（可沿用或按既有規則執行）。無命令時 command null。
審查使用 validate_review 與 validate_credentials，必要時 action review、command null；不偽造 review-run 通過。
item 對帳使用 check_items 與目前 staged paths；不代填交付證據。全條件通過時 action finish、command null，指出仍需確認提交訊息與範圍；不宣稱 commit gate 已放行。
僅捕捉預期 RuleViolation 作為建議缺口；操作錯誤由既有 CLI 邊界處理。不得修改 manifest、state、index、來源、log 或啟動驗證／模型／提交。注意 validate_review 的 self 分支會 git write-tree：需使用唯讀替代取得 index tree 或避免該副作用，維持同一審查規則來源。

## 驗收
真實子程序測試覆蓋 stale verification、缺 review、未完成 task、partial、ready_to_commit 恢復、未知／多 run、唯讀副作用。沿用既有 CLI 回歸，新增必要行為測試。格式檢查本次 Python 檔案，全套 unittest 通過。以本次 run 執行 next 保存實際輸出，確認建議符合當前狀態；此證據不代表完整流程試用已完成。
無開放業務問題。
