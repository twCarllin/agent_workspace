AGENT WORKSPACE · 新工作流程

新工作進來後，
怎麼運作？

先決定需要多少檢查，再執行工作。小修改走短路徑；需要規劃的工作留下計畫、審查與驗證證據。

30 秒講法：收到工作 → 釐清與分級 → 確認計畫 → 實作 → 獨立審查 → 驗證 → 提交。修正只重審差異；符合條件的驗證結果可以重用。

一張圖看完整流程

手機可左右捲動流程圖。Tier B 另用於純專案骨架；一旦加入業務行為，就回到一般分級。流程圖是摘要，實際條件以 Router 與 skill 為準。

每一步，實際在做什麼？

  1. 釐清：確認「要改什麼」與「怎樣才算完成」。先核對工作樹；未提交的既有修改需確認歸屬。
  2. 分級：小修改走 Tier 0；清楚且可控制的工作走 Tier 1；需要完整規格或處理重要契約的工作走 Tier 2。
  3. 確認：Tier 1／2 先提供計畫。已有明確授權的同一範圍，不重複請求確認；新增範圍或未決問題才需要裁決。
  4. 實作：主 agent 或 code-writer 按工作單修改。Codex／Claude Adapter 負責轉換執行方式；通常選一個工具。
  5. 審查：寫的人與審的人分開。預設 checker 核對證據；需要看實作、或遇到升級條件時，由 reviewer 審 diff。邊界類工作直接派 reviewer。
  6. 驗證：依完成條件測試。Tier 2 實作期間跑相關測試，提交前跑完整回歸；Tier 1 收尾跑累積相關測試。功能正確性的本地驗證是提交 gate。
  7. 收尾：憑據通過 → 必要歸檔 → prepare → commit → finalize。最後才把 run 標為完成，並記錄真正的 commit SHA。

現在，哪裡會比較快？

審查少重複

首輪完整，修正看差異

首輪審完整 task。修正後，比對已審版本與目前 index，只審改動與受影響部分；未解問題與契約仍需保留。

驗證有條件重用

相同輸入，沿用成功證據

明確使用 --reuse，且指令、驗證輸入與環境相同，才重用成功結果。純說明文件可不觸發功能重驗；程式、測試、設定與流程 skill 改變則重驗。

測試分段執行

相關測試先跑，最後完整回歸

Tier 2 不在每次小修正後跑整套。新增變更、失敗或證據失效時才重驗。live CLI 只跑本次受影響案例，不使用本地快取。

例子：新增 CSV 匯出

收到需求：「把查詢結果匯出 CSV，要保留目前的欄位順序。」

先分級：若沿用既有查詢與匯出介面，需求清楚，可能走 Tier 1；若要改公開資料契約、權限規則或需求仍有重大歧義，則走 Tier 2。先列判級理由，不只看名稱或行數。

執行：確認欄位、空資料與編碼的驗收條件 → 修改 → 獨立審查 → 相關測試。若 reviewer 要求修正編碼，只重審該修正與相關契約。符合證據條件後提交。

遇到例外時

工作做到一半，session 中斷怎麼辦？

讀取 run、eval_state、staging 與證據，確認停在哪一步。已通過的 task 不重跑；無法核實的審查結論不靠記憶沿用。

模型、登入或 hook 無法使用呢？

記為受阻，保存現場與錯誤。不能偷偷換模型、關閉 gate，或把未執行的案例當作通過。目前 Codex 使用 gpt-6.1-sol；Claude Code CLI 實際驗證仍依既有決定延期。

這樣就完全不依賴 Codex 或 Claude Code 了嗎？

工作規則與證據放在共用核心。執行仍需要一個 AI 工具；換工具時由 Adapter 處理命令、事件與權限差異。工具內部對話與推理狀態不保證可轉移。
