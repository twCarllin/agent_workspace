## 全域實作硬約束（所有實作 item 一體適用，逐條帶入）

**H1 — 最小偏離設計（risk 面向 5，實作核心；違反即子目錄型專案全面誤擋）**
`run_hook()`（`.claude/hooks/eval_gates.py:308-309`）的 root 解析，只有在確認「tool call 來自與 `CLAUDE_PROJECT_DIR` 不同的 git 工作區」時才改變行為，其餘一律原樣回傳 `CLAUDE_PROJECT_DIR`。逐條裁示（usage 開放問題，全採預設）：
- `payload` 無 `cwd` 鍵 → 嚴格回 `CLAUDE_PROJECT_DIR`（HITL 裁示 2）。**不採 `os.getcwd()`**：risk 報告面向 5 的 pseudo-code 寫「退回 os.getcwd() 後同上」已被裁示正式敉平作廢，一律以「嚴格回 CPD」為準，實作不得依該 pseudo-code 的 `os.getcwd()` 措辭。（`CPD` 本身為 None 時才落到 `os.getcwd()`，此與現行 `:308` 末端退路一致。）
- 原始字串 `CLAUDE_PROJECT_DIR == payload.cwd` → 直接回 `CLAUDE_PROJECT_DIR`、**跳過 git**（HITL 裁示 3 效能短路，覆蓋主工作區最熱路徑）。
- 否則對 `payload.cwd` 與 `CLAUDE_PROJECT_DIR` **各跑一次** `git rev-parse --show-toplevel`；兩者皆成功且 toplevel 不相等 → 回 `cwd` 的 toplevel（唯一改變行為的分支）；其餘所有情況（任一失敗、或相等）→ 回 `CLAUDE_PROJECT_DIR`（HITL 裁示 5，不加特殊分支）。各跑一次 git 是為吸收 symlink／尾斜線差異（usage 正確性假設 3），故字串不等仍須走 git 比對、不可只靠字串。

**H2 — 絕不拋例外／絕不 fail-open（risk 面向 4；比鎖死更危險）**
hook exit code 語義：0 放行／2 攔截／**其他值＝非阻斷性錯誤（工具照常執行）**。任何未捕捉例外會讓 gate 靜默 fail-open。`git rev-parse` 子進程一律：參數 list 形式（`["git", "-C", <path>, "rev-parse", "--show-toplevel"]`）不經 shell（risk 面向 2 防注入）、`capture_output=True`（吃掉 stderr，見 H3）、`timeout=5`（HITL 裁示 4）、以 `try/except (OSError, subprocess.SubprocessError)` 包覆（涵蓋 `TimeoutExpired`）；任何失敗一律回 `CLAUDE_PROJECT_DIR`。沿用既有樣板 `eval_gates.py:327-333`（`git diff --cached` 的 fail-open 形）。解析失敗一律退回現行行為。

**H3 — 非 git 目錄實測事實**：`git -C <非git目錄> rev-parse --show-toplevel` → exit 128、stderr 含 `fatal: not a git repository`。必須 `capture_output=True` 吞掉，否則污染 hook 的 stderr。

**H4 — 基石假設已由主 flow 實測坐實（可直接引用、不需重測，usage 正確性假設 2）**：真實 worktree 下 `git rev-parse --show-toplevel` 回 worktree 根、與主 repo 根字串不同；worktree 子目錄回 worktree 根；主 repo 子目錄回主 repo 根。

**H5 — 慣例遵循（impact §2）**：無 logging 模組；helper 前綴底線命名（如 `_git_toplevel`）；module 常數大寫；不新增讀檔 helper（既有樣板已足）。不改任何 gate 的**判定內容**（Spec 非目標 1）、不改 `.claude/settings.json` 註冊（非目標 2）。
