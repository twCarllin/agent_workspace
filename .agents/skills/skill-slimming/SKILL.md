# Skill Slimming（瘦身作業檢查清單）

> 核心取捨：**省下的 token vs 失去的控制**。瘦身的收益是每次載入省 token；風險是弱化硬規則、斷開投放路徑、複製品漂移。本清單逐項守住風險面，收益不划算時停手。

## 1. 範圍界定（動工前先圈）

- 瘦身對象＝**會進 LLM context 的 prose**：`.agents/skills/*/SKILL.md` 與其 `references/`、`.claude/agents/*.md`、.agent-flow/ROUTER.md。
- **不屬瘦身對象**：script（`.claude/hooks/*.py` 等）、tests、fixtures、`run/` 溯源檔——它們不進 context，壓了沒收益；要改是 refactor，另走判級。
- 動工前列出本次要壓的檔案清單與各檔現行行數（收尾對照）。

## 2. 不可弱化清單（壓縮只改表述，不得改語義）

逐段壓縮時，遇下列內容**只准改寫表述、不准改變語義**；語義要變＝需求變更，須使用者裁決，不是瘦身：

- **硬性 gate 語句**（「不可」「必須」「硬性」「gate」句），與 hook 攔截條件對應者連措辭都少動——hook 的 stderr 訊息可能引用原文。
- **憑據要求**（「必附」「留痕」「憑據」句）——刪掉的憑據要求不會報錯，只會讓稽核靜默失明。
- **HITL／防濫用條款**（「必經使用者確認」「agent 不可自行」句式）——這些句子的冗餘是刻意的防線，不是待壓縮的贅字。
- **標 `（R-NNN）` 的規則**：改前先讀 `retro/RETRO.md` 對應條目，確認改寫不重開該失敗；改後條目引用標記保留。

## 3. 結構檢查（壓縮的正路是收斂重列，不是刪句）

- **單一枚舉點（R-007）**：同一清單／規則在多處重列者，收斂到一個枚舉點、其餘改指向式引用（「依 X 的清單」）——這是最安全的瘦身來源；指向時**不得 inline 附推導結果**（那是另一份會漂移的重列）。
- **投放路徑（R-002）**：內容搬動或改指向後，逐一確認原執行者的載入路徑仍讀得到該規則（該檔在其 skill 載入鏈或 agent 定義內；不在→內容留在原處或換收件人，不可只搬走）。

## 4. 停損判準（每檔各判）

- 預估「剩餘可壓段落每次載入省下的 token」低於「逐條核對第 2、3 節的成本」→ **停手**，不追求壓好壓滿。
- 停手時留痕三要素（記入本次變更回報或 run manifest）：**查了什麼**（已核對的檔與節）、**沒查什麼**（未展開的檔與節）、**為何停**（收益低於成本的一句判斷）。

## 5. 驗收（收尾必做）

- **逐條語義保持核對**：對第 2 節四類硬規則，壓縮前後逐條對照（原句 → 新句），確認語義不變——不接受「整段重寫、大意相同」式驗收。
- **實體副本同步**：被壓的檔若有部署副本（`~/.claude/.agents/skills/`、`~/.claude/agents/` 鏡像），同 diff 同步並貼 `diff -q` 無差異憑據；漏同步＝doctor 會報、且兩份漂移比沒瘦身更糟。
- 回報行數對照（各檔壓縮前 → 後）與停損留痕。
