# 任務與背景資料

依 [OpenAI 最佳做法](https://learn.chatgpt.com/guides/best-practices) 整理；以下是本專案對兩種 harness 的應用。

- 派工寫清楚目標、相關背景、限制與完成條件。附必要的檔案與原文契約。
- 入口保留長期規則與可執行驗證指令。流程細節依 Router 選定的 skill 載入。
- 多步或有歧義的工作先建立計畫；單一工作在同一 run 完成，分支工作才隔離。
- 實作交付附測試證據與限制；審查依實際變更範圍進行。
- skill 各負責一種工作，寫明輸入、輸出與觸發條件；先用代表案例驗證。
- 外部工具須解決實際資料需求。流程穩定後才考慮排程。

模型值由專案政策設定。此指南不自動變更已指定的模型或權限。

## 穩定期與成本觀察

本次改善完成後，先觀察 3 個真實工作，再決定是否調整流程。沿用 run 的事件、驗證及派工紀錄，不新增驗收 gate。用 `python3 .agent-flow/scripts/stats.py --dir run` 查看已記錄的升級原因、驗證執行／重用與耗時、packet 缺資料原因。原生 agent 沒有 dispatch 紀錄時，不推算其呼叫時間或 token。

缺逐輪結果時，首次檢核通過率標為無記錄；最終通過不等於首次通過。相同命令重複執行是觀察信號，可能因修正或輸入改變而必要，不能直接當成浪費。階段間事件時距包含等待，不能當成主動工時。入口字元減少不能換算為總 token 或完成時間改善。

文件搬移時，同步檢查共用技能文件來源、部署結果、文件引用與結構測試。只更新路徑與覆蓋範圍，保留原有斷言。共用文件來源見 `.agent-flow/scripts/document_inventory.py`。
